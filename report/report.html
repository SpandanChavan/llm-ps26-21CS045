1. Problem Understanding

Many students understand arithmetic but struggle to turn a word problem into the right sequence of operations. The aim of this project is a tool that takes a word problem in plain English, solves it step by step, explains each step in simple words and gives a clear final answer. Because language models can make arithmetic slips, every answer is independently re-checked with Python before it is shown.

2. Approach and Prompt Design

  • Model: GPT-OSS 120B through the free Groq API, temperature 0.1 for consistent answers.
  • System prompt: the model acts as a patient maths tutor, is told to think step by step, and must follow a fixed format: Given, To find, Step 1 to n, then the final answer on the last line.
  • Few-shot example: one fully solved problem shows the exact format, which makes the output reliable to parse.
  • Verification hook: the model also writes the arithmetic as one expression, e.g. EXPRESSION: 540/(360/4). SymPy evaluates it (only digits and operators are allowed, so no unsafe code can run) and compares it with the final answer.

3. Implementation

  • Stack: Python, FastAPI (backend), HTML/CSS/JavaScript (frontend), Groq API, SymPy.
  • solver.py builds the prompt, calls the model, parses steps, expression and answer with regular expressions, and verifies the result with SymPy.
  • app.py serves the web page and a /api/solve endpoint. The API key is kept in a git-ignored .env file.

User interface (static/index.html), designed to keep the student focused:

  • Question slip: one large input that highlights every number it finds, so missing data is easy to spot.
  • Topic index: six sample problems to start from.
  • Answer sheet: steps numbered in a margin, final answer boxed, and the SymPy result shown as a "checked" stamp.
  • Learn mode: shows one step at a time and hides the answer until the student has tried each step.
  • Dark mode for comfortable night study.
  • Solve history: past problems saved in the browser and reopened without another API call.

5. Observations and Limitations

  • The fixed step format made solutions easy to follow and reliable to parse.
  • The SymPy check catches cases where the explanation and the final number disagree.
  • Testing showed the model sometimes replied in LaTeX; this was fixed with a "plain text only" rule in the prompt and a clean-up step in the UI.
  • Limitations: needs internet and an API key; the check confirms the arithmetic, not whether the chosen method is correct; diagrams and images are not supported.

6. Conclusion and Future Scope

Solvely is a working LLM tutor that explains word problems step by step and checks its own arithmetic. Future work: Hindi and Marathi support, checking the method symbolically with SymPy, photo input for textbook problems, and a practice mode that generates similar problems.
